# campaign-service

Campaign CRUD and orchestration for MCP Factory: lifecycle, budget tracking, run coordination.

## CRITICAL: read-only by default

When the user shares logs, errors or bug reports: ONLY diagnose and explain. NEVER write code, branch or open PRs unless explicitly asked to implement a fix (the same logs often go to several agents in parallel for analysis). Before ANY structural change (endpoints, DAG nodes, services, schema, workflows): stop and ask. The root cause may be in another service.

## THE OWNER RULES (override everything below)

A campaign's STATUS is the CUSTOMER's statement of intent; nothing else changes it. FUNDING and RUNNING are different acts (2026-09-06: conflating them left 5 brands with duplicate live campaigns and resurrected deliberately stopped ones, ~$37 to 4 customers).

1. **MONEY NEVER STARTS ANYTHING.** A funded ceiling provisions no campaign. Deleted: `ensureFundedFunnelCampaigns`, `fundedPairs`, `provisionFundedPairsForQuietBrands`, `funnelCampaignName`, the "resume a funded stopped row" branch, `brand-sales-funnels-client.ts`, `feature-sales-funnels-client.ts`, `feature-workflow-client.ts`, the `funded*` helpers on the budget client. Billing is read for one thing: what an EXISTING campaign's sales funnel caps allow. "Why isn't it running" = "nobody launched it".
2. **A CAMPAIGN THAT EXISTS IS NEVER CREATED AGAIN.** `POST /campaigns` matches the identity's incumbent WHATEVER ITS STATUS (live first, then latest stopped) and hands it back STARTED (it is only ever a person's act). The unique index is partial on `ongoing`; prod has 663 stopped rows sharing 33 identities, history is never rewritten, so the guard lives in the LOOKUP.
3. **A SYSTEM CONDITION NEVER CHANGES A STATUS** (one exception below). Out of credit, audience exhausted, budget spent, `maxBudgetTotalUsd`, `maxLeads`: each blocks the RUN only; it runs again on a later tick. `autoStopCampaign`/`autoStopped` are gone from gate-check; `/end-run` exhaustion marks the audience and reschedules on `NO_SERVEABLE_AUDIENCE_RECHECK_MS`. Nothing RESUMES anything: `campaign-resume.ts`/`isResumableStopReason` are deleted. `STOP_REASONS` = `manual`, `org_teardown` (a person writes) + `payment_declined`, `no_payment_method`. `audience_exhausted`/`max_leads_reached` are RETIRED.
4. **ONE MONEY MODEL (owner 2026-10-14, EDINBURGH-PREFUNNEL-MONEY-RETIRE).** A campaign IS a sales funnel campaign; its money is its sales funnel's caps (max budget and/or max volume per period, billing) and NOTHING else, pay as you go. A campaign that is not a sales funnel unit cannot spend: gate-check refuses `Not a sales funnel campaign` (`NOT_A_SALES_FUNNEL_CAMPAIGN`, right after the one-run guard), the planner holds it `not_a_sales_funnel_campaign` on `FUNDING_RECHECK_MS`, the step trigger skips `not_a_sales_funnel_campaign` (final), the poll payer skips it, start-funded-pair refuses an outreach channel 409 `sales_funnel_required`. Never a fallback to an old ceiling or the brand total. DELETED: billing's per-campaign daily ceilings read (`campaign-budget-client`, `campaign-funding`, split ceiling), own `daily_budget_cents` pacing (column kept, never read for money), items + global modes (`sales-items*`, `global-sales-*`, `brand-sales-budget-client`), `channel-spend`, offer adoption on the tick, the conversion route, `PATCH /brands/:id/daily-budget` (fleet grep 2026-10-14: no caller). `no-legacy.test.ts` fails on a src line reading `/campaign-budget(s)` or `/sales-budget`. Prod at the switch: 112 ongoing campaigns, all units.

Unchanged: the funding HOLD (unfunded waits on `FUNDING_RECHECK_MS`), turn planner and cohorts, fail-CLOSED on unreadable caps, onboarding launch (creates AND starts), `PATCH /campaigns/:id status=activate|stop`.

### The one exception: `payment_declined` / `no_payment_method` (owner, 2026-09-26/27)

An org whose card billing cannot charge stops every campaign.
- **Billing states the verdict**: `lib/payment-hold.ts` reads `GET /internal/accounts/by-org/:orgId/payment-outlook`; `state === "charge_blocked"` ⟺ held, `blockedReason` carried verbatim. 404 = not held. `blockedReason: no_chargeable_card` maps to stop reason/refusal `no_payment_method` (nothing was declined); every other reason is `payment_declined`.
- **Sweep** (`lib/payment-hold-sweep.ts`): first thing every tick, own `PAYMENT_HOLD_RECHECK_MS` (10 min). Stops all ongoing campaigns of a held org (`stopOrgCampaignsWithHistory`, source `payment_hold`); a campaign already stopped keeps its reason. Fail-SOFT.
- **Every start path refuses a held org** (`POST /campaigns`, `POST /campaigns/start-funded-pair`, `PATCH status=activate`) with **409** `{error, reason, blockedReason}` (`error` is customer-facing English the dashboard renders verbatim), whatever stopped the campaign. Billing unreadable = **502** `billing_unavailable`.
- **NOTHING RESUMES AUTOMATICALLY**: the customer presses start once billing stops saying `charge_blocked`. Owner accepted; auto-resume would be the retired resume sweep.
- `tests/setup.ts` mocks `lib/payment-hold.js` to "not held"; `tests/unit/payment-hold.test.ts` uses `vi.importActual`.

- **A deprecated workflow (410) is never asked for again** (`lib/retired-workflow.ts`, `lib/workflow-refusal.ts`): every dispatcher (scheduler, step trigger, selected-dispatch) answers a 410 once with workflow-service's `upgradedToWorkflowSlug`, else the channel's newest live dynasty other than the dead one, and dispatches it in the same breath; when the dead slug is the stored fallback, `workflow_slug` is REPLACED (guarded on the dead value; status untouched). No live workflow = the original refusal rethrows. Why: an unrankable grid (brand with no return economics: every `costPerOutcomeUsd` null) always falls back to the stored slug (prod 2026-10-09, campaign 1e95a4c3 on `-rudder`, 3 days, ~130 recoveries/h).
- **An outreach campaign whose every lead source is OFF is HELD, not run** (`lib/sources-off-hold.ts`, scheduler): same read lead-service refuses on (`sourceCampaignsFeeding`: rows exist, none `ongoing`); entry legs only (catalogue asked only then; unreadable = not held); `campaign-hold` reason `sources_off`, recheck `SOURCES_OFF_RECHECK_MS` (10 min), status untouched. Why: each refused serve came back as `stopCampaign` and marked an audience exhausted, ~1 run/11s, heading for refill + client email (1e95a4c3, 2026-10-09).
- **A run never goes out with nobody to serve** (`TriggerSelection.noServeableAudience`): the grid lists audiences but every one is freshly exhausted = no dispatch. Scheduler holds (`campaign-hold` `no_serveable_audience`, `NO_SERVEABLE_AUDIENCE_RECHECK_MS`), step trigger skips `no_serveable_audience`, a person's start parks `next_run_at` on the same recheck. A grid listing NO audience, or any selection fallback, dispatches as before. Why: 1e95a4c3, 2026-10-09/10, 120 runs reached lead-service with no audience (`no_audience`) while every audience sat in a 24h mark left by `source_campaign_off` refusals.
- **A scheduler dispatch that fails is a failed run** (`backOffFailedDispatch`): refused execution, no anchor run, missing fields all record the streak, set a future `next_run_at` (only while still NULL) and reach the `campaign_failing` alert. Left NULL, the stuck sweep re-claims it every tick, invisibly.
- **A campaign failing every run backs off and is noticed, never stopped** (#407, `src/lib/run-failure-backoff.ts`, migration 0061): `/end-run` keeps the streak on the row (`consecutive_run_failures`, `failing_since`, `last_run_failure_at`, `failure_alerted_at`). Failure on an ONGOING campaign increments (a failure > 1h after the last starts over); ANY success resets (alert latch kept). Delay: 60s for failures 1-3, then 2/4/8/16 min, ceiling 30 min. At 8 in a row (~33 min) ONE staff alert per 24h per campaign: atomic claim in the UPDATE, `POST /platform-send` eventType `campaign_failing` WITH `x-user-id` (campaign owner, else the run's user: a userless send 502s at billing authorize) (transactional-email-service owns template, staff list, per-campaign-day dedup), fire-and-forget, claim released on a failed send. Step trigger skips `failure_backoff` while a widened interval runs. Read: `GET /internal/campaigns/failing` (`runHealth.state` healthy|retrying|failing). Thresholds come from the 30-day streak histogram in the module header; never auto-stop, never email the customer.
- **Turn-planner holds say so**: every hold that parks a campaign on its own cadence emits one `campaign-hold` event (`src/lib/turn-hold-event.ts`) with `reason` (`unfunded`, `budgets_unreadable`, `daily_ceiling_reached`, `planning_failed`), the figures and `nextRunAt`, riding the campaign's ancestor run (`parent_run_id`; none = warn, never an invented one), emitted AFTER planning, fail-SOFT. The 60s TURN defer and cohort in-flight defer stay SILENT. Levels: spent ceiling / unfunded = `info`; failed read / planner throw = `warn`. Diagnose: `SELECT created_at, event, level, detail FROM run_events WHERE campaign_id='<id>' ORDER BY created_at DESC LIMIT 5;`

## History and reads other services use

- **Status history is RECORDED, never reconstructed** (migration 0057). `campaign_status_transitions` is append-only; `src/lib/campaign-status-history.ts` `setCampaignStatus` is the ONLY place a status is written (update + transition in ONE transaction; the create route writes the BIRTH in its own). `no-legacy.test.ts` fails on any `.update(campaigns)`/`.insert(campaigns)` setting `status`/`stopReason` elsewhere. `campaign_audience_availability` stores BOTH states, one row per EPISODE, written by `/end-run` only on a FLIP. `campaign_audience_exhaustion` is a PERIOD (`exhausted_at`, `last_observed_at` (TTL read), `ended_at` + `end_reason` `served`|`lapsed`; partial unique index: one open period per pair).
- **Nothing backfilled; `not_recorded` is never collapsed to `stopped`.** Migration 0057 wrote one `record_opened` row per campaign at its own timestamp (never `created_at`/`updated_at`). `earning` is `null` + `unknownReason` when either axis is unknown; responses carry `statusRecordedSince`/`audienceRecordedSince`.
- **Reads** (`requireApiKey`): `GET /internal/campaigns/:id/earning-history?from&to` and batch `POST /internal/campaigns/earning-history {campaignIds, from, to}`. A day = UTC calendar day evaluated at its END (or now); requested campaigns with nothing recorded are still returned `not_recorded`. NO money figure computed here (billing's); grain is the CAMPAIGN (never revive the brand pause table for this).
- **`GET /internal/campaigns/recurring-status?orgId=&brandId=`** (`src/lib/recurring-status.ts`), for billing's MRR: `running` = `status==='ongoing'`; `executedByPlatform` = `workflow_slug IS NOT NULL`; `kind` = `proactive` ⟺ catalogue leg has NO `fromStep` (null + `kindUnknownReason` if leg unknown; unreadable catalogue 502); `audience` = CURRENT availability period (none = `not_recorded`, `allAudiencesExhausted: null`); `recurring` = running ∧ platform ∧ proactive ∧ not exhausted, null only when it turns on an unknown. A READ, no money. **`kind` is a dependency of instantly-service** (FORM-ANSWER-LATENCY-1014, v0.83.78): `reactive` = the campaign's first email answers a person's own action and is sent at once; keep the field and its values stable.
- **Mission status notification** (`lib/mission-status-notification.ts`): after a status write COMMITS, `setCampaignStatus` fire-and-forgets billing `POST /internal/brands/:brandId/mission-status-changed` (`{campaignId, featureSlug, offerId, legKey, fromStatus, toStatus}` + x-org-id/x-user-id/x-run-id/x-email; billing writes the staff email). Only a person's move (sources `create`, `patch`, `create_restart`, `start_funded_pair`, via `actor`), only when `from !== to`; a person CREATING a campaign ongoing (both insert paths, `signalCampaignBirth`) sends `fromStatus: null` (billing re-prices a subscriber's plan and invoices budgets turned ON); never awaited, failures swallowed. Source literals are strings because `campaign-status-history.ts` imports this module (cycle); the unit test pins them to `TRANSITION_SOURCES`.
- **Brand transfer** `POST /internal/transfer-brand` (`src/lib/brand-transfer.ts`, one transaction, idempotent): moves `campaigns` (naming the brand alone, `brand_id` or single-element `brand_ids`), `campaign_status_transitions`, `campaign_audience_availability`, `brand_pause_transitions`, and `*_snapshot_20260926` tables where they exist; brand id rewritten only on rows now under the TARGET org; co-branded campaigns stay (`coBrandedSkipped`); history not money; a target-org campaign-name collision = 409. A NEW table carrying `org_id` must be added there and to `tests/integration/transfer-brand.test.ts`.
- **`campaigns.status` is `ongoing` | `stopped`; there is NO `active`** (a `status='active'` query returns empty and falsely reads "nothing runs"). `GET /campaigns?status=` serves that vocabulary (`CampaignStatusEnum`), unrecognised = 400, never an unfiltered list; no aliasing. `limit` is optional (absent = every match), reads one row past the cap and returns `hasMore`; no cursor.
- **Frozen-history tests**: assert only the direction that stays true (what a frozen migration names is in scope), never that a growing live set is fully covered by it (`tests/unit/funnel-owner-decision.test.ts`).
