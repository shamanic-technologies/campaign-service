Campaign CRUD and orchestration for MCP Factory: lifecycle, budget tracking, run coordination.

NEVER write code, branch or open PRs unless explicitly asked to implement a fix (the same logs often go to several agents in parallel for analysis). ## THE OWNER RULES (override everything below)

A campaign's STATUS is the CUSTOMER's statement of intent; nothing else changes it. FUNDING and RUNNING are different acts (2026-09-06: conflating them left 5 brands with duplicate live campaigns and resurrected deliberately stopped ones, ~$37 to 4 customers).

1. **MONEY NEVER STARTS ANYTHING.** A funded ceiling provisions no campaign. Deleted: `ensureFundedFunnelCampaigns`, `fundedPairs`, `provisionFundedPairsForQuietBrands`, `funnelCampaignName`, the "resume a funded stopped row" branch, `brand-sales-funnels-client.ts`, `feature-sales-funnels-client.ts`, `feature-workflow-client.ts`, the `funded*` helpers on the budget client. Billing is read for two things only: is an EXISTING campaign funded (the hold), and which ceiling paces it. "Why isn't it running" = "nobody launched it".
2. **A CAMPAIGN THAT EXISTS IS NEVER CREATED AGAIN.** `POST /campaigns` matches the identity's incumbent WHATEVER ITS STATUS (live first, then latest stopped) and hands it back STARTED (it is only ever a person's act). The unique index is partial on `ongoing`; prod has 663 stopped rows sharing 33 identities, history is never rewritten, so the guard lives in the LOOKUP.
3. **A SYSTEM CONDITION NEVER CHANGES A STATUS** (one exception below). Out of credit, audience exhausted, budget spent, `maxBudgetTotalUsd`, `maxLeads`: each blocks the RUN only; it runs again on a later tick. `autoStopCampaign`/`autoStopped` are gone from gate-check; `/end-run` exhaustion marks the audience and reschedules on `NO_SERVEABLE_AUDIENCE_RECHECK_MS`. Nothing RESUMES anything: `campaign-resume.ts`/`isResumableStopReason` are deleted. `STOP_REASONS` = `manual`, `org_teardown` (a person writes) + `payment_declined`, `no_payment_method`. `audience_exhausted`/`max_leads_reached` are RETIRED.
4. **A FUNDED CEILING NAMING NO LEG IS A LOUD NAMED ERROR.** Never defaulted to a coarser figure, never skipped silently: `legKeylessFundedCeilings` + `reportLegKeylessCeilings` `console.error` org/brand/funnel/channel/offer/cents/grain, deduped per identity on the 10-min cadence. It does NOT hold the brand.

Unchanged: the funding HOLD (unfunded waits on `FUNDING_RECHECK_MS`), ceiling precedence, turn planner and cohorts, fail-CLOSED on an unreadable ceiling, onboarding launch (creates AND starts), `PATCH /campaigns/:id status=activate|stop`, offer attribution adoption.

### The one exception: `payment_declined` / `no_payment_method` (owner, 2026-09-26/27)

An org whose card billing cannot charge stops every campaign.
- **Billing states the verdict**: `lib/payment-hold.ts` reads `GET /internal/accounts/by-org/:orgId/payment-outlook`; `state === "charge_blocked"` ⟺ held, `blockedReason` carried verbatim. 404 = not held. `blockedReason: no_chargeable_card` maps to stop reason/refusal `no_payment_method` (nothing was declined); every other reason is `payment_declined`.
- **Sweep** (`lib/payment-hold-sweep.ts`): first thing every tick, own `PAYMENT_HOLD_RECHECK_MS` (10 min). Stops all ongoing campaigns of a held org (`stopOrgCampaignsWithHistory`, source `payment_hold`); a campaign already stopped keeps its reason. Fail-SOFT.
- **Every start path refuses a held org** (`POST /campaigns`, `POST /campaigns/start-funded-pair`, `PATCH status=activate`) with **409** `{error, reason, blockedReason}` (`error` is customer-facing English the dashboard renders verbatim), whatever stopped the campaign. Billing unreadable = **502** `billing_unavailable`.
- **NOTHING RESUMES AUTOMATICALLY**: the customer presses start once billing stops saying `charge_blocked`. Owner accepted; auto-resume would be the retired resume sweep.
- `tests/setup.ts` mocks `lib/payment-hold.js` to "not held"; `tests/unit/payment-hold.test.ts` uses `vi.importActual`.

### One proactive ON per offer; reactive ON by default (owner 2026-10-05)

- **Rule 1** (`lib/single-proactive.ts`): a PERSON turning ON a campaign on an ENTRY leg (catalogue `fromStep` null) stops every other ongoing entry-leg campaign of the same (org, offer) IN THE SAME TRANSACTION (`setCampaignStatusWithStops` `displace`, or `stopProactiveReplacedBy` inside an insert tx), reason `manual`, source `proactive_switch`, billing signalled with the same actor. All person starts: `POST /campaigns` (insert + restart), start-funded-pair (insert, restart AND already-running), `PATCH status=activate`; answers carry `stoppedCampaigns`. Advisory xact lock per (org, offer) serializes racing starts. Catalogue read ONLY when another campaign of the offer is live; unreadable then = 502 `catalogue_unavailable`, rolled back. Nothing else ever switches it (no tick/ROI/AI); offers already holding two are left until a person acts.
- **Rule 2** (`lib/reactive-defaults.ts` plans, `routes/campaigns.ts` `applyReactiveDefaults` writes): ticked paths = brand-service `GET /internal/offers/:id/selected-sales-paths` combinationKeys, never stated = `roi > 1` rows of features `GET /offers/:id/sales-paths?scope=catalogue`; each reactive leg worked by a managed platform channel in the sales family with NO row is born ON (source `reactive_default`, billing signalled, funding NOT checked: the hold gates runs). A stopped row is NEVER restarted (person's off, payment hold, teardown). Triggered only by a person: fire-and-forget after a proactive start, and `POST /offers/:offerId/reactive-defaults {brandId}` when a person saves paths. Never a tick.

## `POST /campaigns/start-funded-pair` (a person's act)

Only ever runs because somebody pressed a button; `tests/unit/no-legacy.test.ts` asserts `lib/startable-pair.ts` is imported only by `routes/campaigns.ts` (a scheduler importing it is the deleted question returning).
- Caller states brand, offer, LEG, channel (offer+leg REQUIRED, else `leg_required`). Workflow (re-picked each run), name (derived) and money (billing's) are NOT the caller's: body is `.strict()`.
- Refusal `reason` codes: 400 `leg_required`, `channel_not_paced_here`, `unknown_channel`, `leg_not_performed`; 409 `not_funded`, `no_workflow`; 502 `catalogue_unavailable`, `billing_unavailable`, `workflow_unavailable`. `error` is customer-facing English. "Nothing can run this channel" and "could not read what runs it" stay different answers.

- **Brand transfer** `POST /internal/transfer-brand` (`src/lib/brand-transfer.ts`, one transaction, idempotent): moves `campaigns` (naming the brand alone, `brand_id` or single-element `brand_ids`), `campaign_status_transitions`, `campaign_audience_availability`, `brand_pause_transitions`, and `*_snapshot_20260926` tables where they exist; brand id rewritten only on rows now under the TARGET org; co-branded campaigns stay (`coBrandedSkipped`); history not money; a target-org campaign-name collision = 409. A NEW table carrying `org_id` must be added there and to `tests/integration/transfer-brand.test.ts`.
- **`campaigns.status` is `ongoing` | `stopped`; there is NO `active`** (a `status='active'` query returns empty and falsely reads "nothing runs"). `GET /campaigns?status=` serves that vocabulary (`CampaignStatusEnum`), unrecognised = 400, never an unfiltered list; no aliasing. `limit` is optional (absent = every match), reads one row past the cap and returns `hasMore`; no cursor.
- **Frozen-history tests**: assert only the direction that stays true (what a frozen migration names is in scope), never that a growing live set is fully covered by it (`tests/unit/funnel-owner-decision.test.ts`).

Unit tests need neither.
- **`pnpm` via corepack dies on Node 20.19.1** (`ERR_VM_DYNAMIC_IMPORT_CALLBACK_MISSING`): use `npx --yes pnpm@10 <cmd>`.
- **`db:push` hangs on a column RENAME AND on any NEW table** (interactive "created or renamed?" prompt: the hand-made `*_snapshot_*`/decision tables look like rename candidates; `--force` does not skip it): apply the migration file with `psql "$URL" -v ON_ERROR_STOP=1 -f drizzle/NNNN_*.sql` instead (2026-10-09, 0065).
- **`db:generate` is DEAD** (`drizzle/meta` snapshots froze at `0023`). Migrations are HAND-AUTHORED idempotent SQL: write `drizzle/NNNN_<desc>.sql` (boot-safe: `DROP COLUMN IF EXISTS`, or a `DO $$ … information_schema … IF EXISTS` guard) AND append a `drizzle/meta/_journal.json` entry (next `idx`, matching `tag`, synthetic `when` +100000000 ms). `src/lib/migrations-validator.ts` enforces journal/sql parity and gap-free idx. Boot runs `migrate()` before `listen()`.
- **A raw-SQL migration touching `campaigns.id`/`org_id` MUST cast `::text` on both sides**: `drizzle/0000` made them `uuid`, `schema.ts` says text; a from-scratch replay dies `operator does not exist: text = uuid` at BOOT (service never binds, deploy rolls back). Invisible to `db:push` and unit tests; CI replays from zero. Check with a scratch DB (`campaigns(id uuid, org_id uuid)`, `psql -v ON_ERROR_STOP=1`) and a full `drizzle-kit migrate` from empty. (Cost 2026-09-12, migration 0057.) **Same at RUNTIME: prod and CI have `campaigns.id` uuid while a local `db:push` DB has text**, so a query comparing `campaigns.id` to a CALLER's id passes locally and 500s in CI/prod on a non-uuid value (`invalid input syntax for type uuid`): compare `${campaigns.id}::text = ${id}` (2026-10-09, trigger-events #588).
- **Raw `sql` list params need `sql.join`**, not a bare JS array (`IN (${arr})` binds one composite): `sql.join([...set].map((v) => sql\`${v}\`), sql\`, \`)`. A JS `Date` param is refused: pass `d.toISOString()` with `::timestamptz`. Only integration tests catch these.
- **Workflow dynasties/slugs are DB-resident** (workflow-service `workflows` by `feature_slug, workflow_dynasty_slug`; runs in `workflow_runs`): query the DB, do not grep workflow-service `src` (only fixtures). features-service cannot say which feature a brand is on: the feature comes from the caller (`x-feature-slug`).
